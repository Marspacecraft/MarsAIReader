# 文档目录与纪律

## 纪律（对后续每一次讨论生效）

1. **结论必须落到文档才算定案。** 只出现在对话里的结论视为"未定"，不得据此写代码。
2. **落文档时同时写"为什么"。** 只写"决定用注册表"而不写"因为伪阻塞的保证必须落在一处"，下一个人会把这个决定重新讨论一遍。
3. **一次讨论可能改多份文档。** 改完必须回头检查是否与其它文档矛盾——三份文档比三份代码更容易互相打架。
4. **每份文档有「决定记录」，只追加不删除。** 被推翻的决定标记"已否决 + 原因"，不删掉，否则会被人重新提出。
5. **文档与代码同 PR。** 改了行为不改文档，视同没改。
6. **`docs/generated/` 是生成物**，不手改，改了会被门禁覆盖。
7. **每份文档开头写清"它回答什么问题"。** 两份文档回答同一个问题，就会出现两套事实。
8. **接口的权威定义是头文件，不是文档。** 文档只写约束、理由、失败模式，不复制函数签名——复制就会漂移，而漂移是静默的（参见 `asset-pack-name-contract` 那类事故）。

## 版本约定

- 标题带版本：v0.1 草案 → v0.2 结构定稿 → v1.0 可据以实现。
- 只改措辞不动结构：不升版本。
- 改分层、改决策、改契约：升次版本号，并在「决定记录」里留一行。
